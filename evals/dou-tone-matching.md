# dou-tone Agent 匹配回归用例

这些用例用于人工或 Agent eval，重点检查 discovery 阶段是否根据 `SKILL.md` 的 `name + description` 正确决定是否使用 `dou-tone`。

## 应触发

1. `帮我润色一下这份工作总结，事实和数字别改。`
2. `把这些口述需求整理成给甲方看的正式项目方案。`
3. `这段开题报告语言有点口语，按硕士论文风格深度润色。`
4. `把下面的教学设计改得更自然、正式一些，内容不要扩写。`
5. `把这几条要点整理成一页 PPT 的标题和正文。`
6. `用我的语气把这些材料写成公众号文章，不要有 AI 味。`
7. `重写这段 README，让项目能力和限制更清楚。`

期望：使用 `dou-tone`，并根据任务选择正确改写级别和主场景。

## 不应触发

1. `什么是多模态融合？`
2. `帮我找三篇最新的遥感多标签论文。`
3. `解释一下 softmax 和 sigmoid 的区别。`
4. `这个 Python 报错怎么修？`
5. `把这段英文忠实翻译成中文，不要改写。`
6. `提取这份报告里的所有日期和金额。`
7. `总结这篇论文的方法和实验结果，方便我理解。`
8. `把这份 Word 转成 PDF。`

期望：不要仅因为内容涉及科研、项目、教学或文档而使用 `dou-tone`。

## 组合触发

1. `解释这篇论文的方法，然后把我的理解整理成讨论班汇报稿。`
   - 前半段不需要 `dou-tone`；整理汇报稿阶段使用。
2. `修复这个接口 bug，并帮我写一段 PR 描述。`
   - 代码修复不由 `dou-tone` 负责；PR 描述可使用。
3. `把这份报告生成 DOCX，并顺便润色正文。`
   - 文件生成由文档/Artifact 能力负责；文字层使用 `dou-tone`。
4. `把这段英文翻成中文并改成正式报告口吻。`
   - 翻译与文体改写同时存在，可使用 `dou-tone` 处理改写层。
5. `做一份科研汇报 PPT。`
   - 如果任务包含页面文案写作，可使用 `dou-tone` 的学术 + PPT 规则；幻灯片文件生成仍由 presentation 能力负责。

## 失败判定

出现以下任一情况视为匹配质量问题：

- 仅因主题是科研/教学/项目就自动触发。
- 用户明确要求润色/重写却未触发。
- 触发后一次性加载全部 `references/`。
- 与专业 Skill 或 Artifact Skill 竞争并重复执行其职责。
- 因 Skill 默认规则覆盖用户本轮明确指令。
